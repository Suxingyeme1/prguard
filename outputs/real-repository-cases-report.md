# Real-repository coding gate report

Date: 2026-08-19

PRGuard version: 0.5.1

Provider: DeepSeek `deepseek-v4-pro`, high reasoning

## Outcome

PRGuard produced a verified, minimal one-file Patch for three current public open-source Issues at
frozen commits. This is a small engineering gate, not a general benchmark. The selected terminal
runs resolved 3/3 cases; only 1/3 cases succeeded on its first complete provider invocation. Failed
runs and failed intermediate attempts are frozen alongside successes.

## Case construction and leakage boundary

- Upstream repositories, public Issue URLs, licenses, upstream SHAs, evaluation-base SHAs, and
  environment versions are frozen in [provenance.json](real-repository-cases/provenance.json).
- Agent task text contains only behavior, reproduction, and expected result. Root-cause and
  suggested-fix text from public Issue discussions was deliberately removed.
- Evaluator bases add a public reproduction test. Humanize and PrettyTable also add `_version.py`
  stubs normally generated by their build backend. The exact additions are stored as
  `evaluation-base.patch` under each case.
- There are no hidden tests or gold patches in these cases, and the report does not claim otherwise.
- Source and tests were executed on the host account. The Phase 1 process boundary is not a hostile
  code sandbox; container/network/resource isolation remains future hardening.

## Failures retained as evidence

1. Humanize's first Issue-to-PR invocation returned an Implementer proposal after the 300-second
   logical budget and correctly ended `fix_failed` at 345.879 seconds. The SDK request itself did
   not cancel exactly at the deadline.
2. The first accepted Humanize Issue-to-PR Patch passed the configured tests and independent
   Reviewer, but a later wider check found a new ruff E501. The base file was lint-clean; the real
   problem was that ruff had been omitted from the original task gate. That run is historical
   incomplete-gate evidence, not the selected review-ready Patch.
3. Humanize's selected lint-enabled run rejected a corrupt first diff, supplied structured failure
   evidence, and accepted the second complete replacement Patch after pytest and ruff passed.
4. Inflect's first invocation found the correct one-line logic change but emitted a diff with no
   trailing hunk context. Strict `git apply` rejected it, and the repair turn exhausted the original
   24-call tool budget. A separately recorded rerun with a 40-call cap produced a standard diff and
   passed.
5. The Humanize independent Reviewer returned after its 300-second stage budget and was accepted by
   the then-current runner. PRGuard 0.5.1 now checks the deadline after Reviewer return and fails such
   a result closed. The SDK-level cancellation remains best-effort.

## What can be claimed

- The local Coding Agent can locate and patch code in three unrelated real Python repositories,
  produce standard unified diffs, and pass deterministic public behavior/regression checks.
- One selected real-repository run demonstrates the intended finite repair loop from rejected Patch
  to accepted pytest/ruff result.
- The independent Reviewer mechanism completed on a real repository with isolated read-only context,
  but this set does not measure Review Finding precision/recall or prove net Reviewer benefit.
- No claim is made about arbitrary repositories, hostile-code isolation, GitHub integration, or
  statistically significant task resolution.
