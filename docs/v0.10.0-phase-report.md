# v0.10.0 phase report: hash-bound Shadow Reviewer scorecard

Status: implemented 2026-09-02.

Post-release note: v0.10.1 later obtained an exact-Patch PrettyTable Reviewer result and confirmed
a multi-table regression. The PrettyTable label, counts, and activation decision below describe the
initial scorecard snapshot; see [v0.10.1](v0.10.1-phase-report.md) for the superseding evidence.

## Objective

Turn the existing routing and Reviewer-value case studies into a small, reproducible decision
record. The increment must calculate routing errors and Reviewer cost from frozen artifacts,
preserve evaluator/Agent separation, reject cross-Patch joins, and say when the evidence is too
weak to enable selective Review by default.

This is evaluation support for the Coding Agent product, not a benchmark platform and not a new
Agent role.

## Outcome

`prguard.evaluation` defines strict post-run schemas and derives a `ShadowScorecard`. The loader
accepts only evidence-root-relative regular files, verifies every declared SHA-256, parses the
versioned routing contract, requires `shadow` mode, and checks the frozen routing-policy version.
Reviewer evidence joins only when its Base Commit and candidate Patch SHA-256 match the routing
record. Evaluator models are not exported from `prguard.schemas`, and Fix/Review task contracts do
not contain label fields.

`scripts/build_shadow_scorecard.py` prints deterministic JSON or Markdown without calling a model
or executing repository code. Contract tests regenerate both checked-in views byte-for-byte.
Security tests reject path traversal, route tampering, and a Reviewer record rebound to another
candidate Patch. The public evidence verifier now authenticates the pre-repair regression candidate
as well as the repaired Patch.

## Frozen observations

The scorecard contains three accepted Fix candidates:

| Case | Source | Evaluator label | Recommended route | Paired Reviewer |
| --- | --- | --- | --- | --- |
| PrettyTable #474 source-only | real repository | clean | `skip`, 0/5 | not observed for this exact Patch |
| Humanize #366 source-only | real repository | clean | `review`, 9/5 | not observed for this exact Patch |
| normalization regression | deterministic fixture | defective | `review`, 7/5 | one confirmed incremental finding; one accepted repair |

The derived counts are:

- False Route: 1/2 clean accepted Fixes;
- False Skip: 0/1 defective accepted Fix;
- False Block: 0/0 clean effective Reviews with a same-Patch observation;
- paired Reviewer coverage: 1/3;
- defective cases caught by Reviewer: 1/1 among defective cases with a paired observation;
- observed Reviewer cost: 26.150 seconds, 6,902 input and 1,644 output tokens, one repair round.

`0/0` is intentionally not reported as zero percent. The separate clean Humanize Reviewer run is
still valid Reviewer-cost evidence, but its candidate Patch hash differs from the source-only
routing case, so this scorecard does not join them.

## Activation decision and boundary

Selective Review remains explicit and opt-in. The scorecard records two blockers:

1. paired Reviewer outcome coverage is only 1/3;
2. there is no evaluator-confirmed defective real-repository case.

The observed 0/1 False Skip count therefore does not estimate a production escape rate. The result
shows that the routing contract can select an uncovered regression and that the independent
Reviewer can add one confirmed finding in that case. It does not establish routing calibration,
Reviewer recall across repositories, or net value for every selected Review.

## Verification

The release gate covers unit, integration, contract, and security suites; Ruff; public-evidence
hash verification; reproducible scorecard generation; and wheel/sdist build checks. It passed all
206 tests and authenticated 22 public evidence files. Both the `0.10.0` source distribution and
wheel built successfully. Build-file hashes are not embedded here because this report is itself
part of the source distribution.

The first full run exposed an existing macOS cleanup race: after successfully sending `SIGTERM` to
a completed command's process group, the zero-signal liveness probe can return `PermissionError`.
PRGuard now stops signalling when the numeric group is no longer attributable, avoiding a possible
signal to a reused group. The background-child escape test then passed five consecutive focused
runs and the complete suite.

## Next priority

Run the exact source-only PrettyTable and Humanize Patches through the Independent Reviewer when a
provider credential is available, preserving same-Patch manifests. Add at least one manually
labelled defective Patch in a real public repository, preferably one that passes a plausible narrow
gate but fails a frozen wider regression check. Recompute the same scorecard without changing
`review-routing-v1`. Do not tune the threshold or add a Diagnostician until those observations show
a concrete failure mode.
