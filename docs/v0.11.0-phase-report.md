# v0.11.0 phase report: local natural-language Issue onboarding

Status: implemented 2026-09-03.

## Objective

Remove the requirement that local-repository users hand-author Task JSON, while preserving the
existing Base Commit, execution-policy, Agent-context, and Artifact boundaries.

## Product entry

The new direct path is:

```text
clean local Git repository + HEAD/commit + natural-language Issue
  -> detached frozen checkout
  -> deterministic project-policy discovery
  -> hash-bound FixTask
  -> existing Issue-to-Patch workflow
```

`fix` accepts inline Issue text with `--repository`, or `--issue-file` for longer requirements.
`prepare-local` exposes the same preparation as a two-stage workflow for human or CI inspection.

## Safety and replay behavior

- source repositories must be clean Git toplevels;
- `HEAD` is resolved before provider execution and recorded as a full commit hash;
- the workspace must be outside the source repository;
- the frozen checkout is initialized separately and verified at the exact commit;
- local source hooks and Git user/system configuration are disabled during materialization;
- Issue files must be regular non-symlink UTF-8 files and are limited to 50,000 bytes;
- host or digest-pinned container execution remains an explicit operator choice;
- commands and write scopes still come from reviewed `.prguard.toml` or deterministic discovery,
  never from model prose.

The report records an Issue SHA-256 and the requested/resolved commit. The preparation Manifest
binds the generated Task and report; the downstream Fix produces its normal Patch and Manifest
chain.

## Boundary

PRGuard still does not package dependency installation into the Agent loop. If deterministic policy
discovery cannot identify a safe gate or source scope, onboarding stops and asks for a reviewed
repository policy. Dirty-working-tree capture is intentionally deferred because it needs a separate
hash-bound input contract.
