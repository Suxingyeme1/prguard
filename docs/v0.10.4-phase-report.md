# v0.10.4 phase report: holdout-driven routing and orchestration correction

Status: implemented 2026-09-03.

## Objective

Run the first small real-repository holdout after freezing `review-routing-v2`, retain raw failures
instead of attributing them to the model, and version any deterministic correction without
rewriting prior evidence.

## Real-repository observations

Two evaluator-confirmed clean source-only Patches were run in shadow mode on the server as the
non-root `prguard` account:

| Case | Deterministic gate | v2 route | Reviewer result | Review cost |
| --- | --- | --- | --- | --- |
| Inflect #242 | 5 targeted; 215 passed + 16 xfailed wider | `review` 9/5 | accept, 0 findings | 209.3 s; 258,378 input + 9,418 output tokens |
| python-dotenv #638 | 217 passed + 1 skipped full suite | `review` 7/5 | accept, 0 findings | 94.3 s; 132,878 input + 4,579 output tokens |

The python-dotenv label has evaluator evidence beyond the existing suite: on the frozen Base,
calling `DotEnv.dict()` twice for an empty file calls `parse()` twice; the Candidate calls it once.
The source-only Patch matches upstream merge commit
`3f0e3e0b461cf7127e2753efbdf896bdff31db2e`.

Across these two clean cases, Independent Review added 303.6 seconds and 405,253 input/output
tokens while producing no findings. These are observations, not a general model-quality estimate.

## Routing v3

The python-dotenv route exposed contradictory accounting in v2: pytest was classified as `full`,
yet related test files were treated as not executed. `review-routing-v3` marks every bounded
reachable/related test as covered when a verified full-suite command ran. The exact python-dotenv
route becomes `skip` 0/5; Inflect remains `review` 9/5. Replays of PrettyTable, Humanize, and the
normalization regression keep their v2 decisions.

The policy remains opt-in. The evidence record explicitly says `activation_decision: not_ready`
because there are only two clean observations, python-dotenv informed the correction, and no new
held-out defective case has exercised v3 False Skip behavior.

## Lazy controlled-repair provider

The first python-dotenv run failed before Review with zero provider tokens because Issue-to-PR
eagerly validated a scripted repair fixture. That fixture was irrelevant: the Reviewer later
accepted the same Patch. v0.10.4 passes the repair provider as a lazy source and resolves it only
after `request_changes`. A CLI integration test reproduces the original configuration and proves
that an accepting Review completes without any repair proposal fixture.

## Evidence boundary

The complete server run directories remain private working Artifacts. Twelve nested Manifests from
the two python-dotenv attempts were recursively verified after transfer, the archive hash matched
across hosts, and a credential-pattern scan was clean. The public package contains path-free route,
evaluator, regression, and summary records under
[`evidence/review-routing-v3-holdout`](../evidence/review-routing-v3-holdout/README.md).
