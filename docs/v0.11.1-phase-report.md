# v0.11.1 phase report: explainable project-policy onboarding

Status: implemented 2026-09-03.

## Objective

Make repository adaptation inspectable before spending model tokens or executing target code. The
operator should be able to answer where verification commands and edit boundaries came from, and
an unsupported repository should fail with actionable evidence rather than a generic exception.

## Product entry

`prguard inspect-policy --repository ...` resolves a clean Git Base Commit and emits a structured
report containing:

- repository and requested/resolved Base Commit;
- configuration and layout signals used by discovery;
- exact argv-only pytest/Ruff gates;
- writable, protected, and runtime-only paths;
- warnings, blocking reasons, and next actions;
- a deterministic valid TOML candidate when policy discovery is ready.

Optional Issue text uses the same static symbol-to-test targeting as onboarding. The command does
not invoke a provider, import repository modules, execute tests, create a worktree, or mutate the
source repository.

## Fail-closed behavior

If PRGuard cannot identify an existing safe gate, the report returns `needs_config`, exit code 1,
and no suggested command. Invalid or non-allowlisted `.prguard.toml` commands are reported in the
same structured form. Git/preflight or Issue-file input failures remain usage errors with exit code
2.

The TOML candidate is emitted only after the current policy is valid. It is labelled for review and
must be committed by a maintainer before it becomes repository-owned policy.

## Boundary

The command explains and freezes supported policy; it does not expand the Harness command
allowlist. Repositories without a trustworthy pytest or non-mutating Ruff gate still require a
maintainer decision. Dependency installation and service orchestration remain outside the Agent
loop.
