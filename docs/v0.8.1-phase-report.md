# v0.8.1 phase report: evidence-preserving navigation and gate adaptation

## Outcome

Version 0.8.1 turns a retained PrettyTable failure chain into product corrections rather than
raising the model budget until one run happens to pass. The final live Fix run at exact upstream
commit `3c80d392d32f48b0ab1e368793ddb751dbe41807` produced a source-and-test Patch in one attempt.
The declared related-test gate passed, and the same Patch later passed the complete public pytest
suite.

The claim is deliberately narrow. [PrettyTable #474](https://github.com/prettytable/prettytable/issues/474)
states the off-by-one root cause in its public text, so this case does not measure blind defect
diagnosis. It pressures repository navigation, test selection, project adaptation, bounded tool
orchestration, deterministic verification, and auditable failure handling.

## What the failures showed

### 1. Provider failure evidence vanished

The first rerun ended at the 24-call limit. The old report contained an error string but zero Token
usage and no calls, even though the provider had searched the repository for 44.735 seconds. The
provider adapters now attach non-secret partial evidence to expected failures: provider/model,
response ID, safe metadata, accumulated Token usage, and bounded tool-call records. Fix and Review
runners emit dedicated JSON plus report/Markdown fields, and the recursive Manifest hashes them.

The corrected report recovered 24 calls and 72,646 input / 2,707 output / 65,792 cached tokens.
Hidden reasoning and credentials remain excluded.

### 2. A realistic source module was invisible

`src/prettytable/prettytable.py` is about 121 KB, above the previous 100 KB default. Text search
skipped it, the AST index reported one skipped file, and `find_symbols("from_html")` returned no
definition. With the bounded default at 250 KB, the same tools locate:

- `from_html` at `src/prettytable/prettytable.py:3242`;
- the padding calculation and loop at lines 3202-3203;
- `tests/test_html.py` as the symbol-related test file.

The schema still caps a task at 1 MB per file; the AST keeps its 2,000-file, 20 MB total-source, and
shared response/context budgets.

### 3. Test targeting discarded symbol precision

Onboarding found `from_html` but passed only `src/prettytable/prettytable.py` into related-test
ranking. Filename evidence then selected `tests/test_prettytable.py`. Passing the qualified symbol
`prettytable.prettytable.from_html` selects `tests/test_html.py`. A contract case now covers a
large module where module-filename and symbol-specific tests intentionally disagree.

### 4. The model had no terminal slot

After navigation was repaired, a run read the defect and tests but consumed all 24 calls. The next
submission was rejected because terminal submission counted against the same limit. v0.8.1 treats
`max_tool_calls` as a read budget and permits exactly one terminal submission after it. Every read
result reports used/remaining calls and asks the model to converge in the last three. Additional
reads still fail closed and retain partial evidence. Reviewer submission uses the same rule.

### 5. Inferred lint was not repository policy

The next run submitted a correct-looking Patch in 19 calls, then failed `ruff check .`. The frozen
Base Commit already had 13 findings under PRGuard's installed Ruff, and the target configuration
enabled fixes. The repair turn chased unrelated historical lint and exhausted its budget.

PRGuard no longer equates `[tool.ruff]` presence with an approved gate. Generic onboarding infers
pytest only; reviewed `.prguard.toml` may explicitly add `ruff check --no-fix`. Every declared
non-pytest gate must pass at the Base Commit before provider invocation. The Harness also compares
the Candidate diff before and after commands and policy-blocks any verification-induced mutation.

### 6. Runtime adaptation needed a real regression check

The first wider run passed 338 tests but failed one version-format assertion against the generated
Hatch VCS scaffold. `0+prguard`, then `0.0.0+prguard`, exposed repository assumptions about dot
count and a numeric final character. The generic placeholder is now the conservative PEP 440
version `0.0.0` with tuple `(0, 0, 0)`. It remains runtime-only, protected, hash-checked, and absent
from the delivered Patch.

## Boundary and next priority

- The accepted gate proves behavior only at the frozen commit and environment.
- Tool counts and Chat Completions Token counts are cumulative across turns; high cache hits do not
  remove latency or make unconditional large budgets desirable.
- The wider check is post-run evidence. Repositories that require it for acceptance should declare
  it in reviewed policy rather than relying only on automatic related-test narrowing.
- Automatic project adaptation is still Python-specific and does not install dependencies.

The next useful product step is another public Issue whose text does not disclose the source-level
fix, followed by selective Reviewer routing based on actual risk signals. A Diagnostician remains
deferred: these failures were orchestration and environment facts that deterministic code could
classify directly.
