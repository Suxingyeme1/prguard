# v0.8.0 phase report: onboarding, code intelligence, and structured edits

## Outcome

Version 0.8.0 closes three product gaps in the Issue-to-Patch path:

1. A canonical public GitHub Issue can be frozen into a replayable local task without hand-writing
   the normal JSON contract.
2. The Implementer and Reviewer can navigate Python symbols, imports, static call relationships,
   references, and related tests in addition to bounded text search.
3. A live provider can submit exact text edits; PRGuard applies them locally and asks Git to author
   the Base-Commit-relative unified diff.

The CLI subsequently composes onboarding and Fix execution when `prguard fix` receives a canonical
GitHub Issue URL. The intermediate Task, preparation report, and preparation Manifest remain stored
under the required workspace; `prepare-github` remains available as an explicit approval point.

The composed command received the real Humanize #366 URL, used a verified same-origin local clone
as a Git-object cache, replayed the accepted structured proposal, and completed preparation,
collection readiness, 78 tests, Ruff, and both Manifest checks while leaving the checkout clean.
Because the provider was scripted, this is command-composition/replay evidence—not an additional
live-model task-resolution result.

The accepted claim remains narrow: a Patch passed the declared gate at a specific commit. Static
analysis, discovered tests, and a single repository case do not prove semantic correctness.

## Frozen real-repository case

The end-to-end gate used [Humanize #366](https://github.com/python-humanize/humanize/issues/366) at
commit `ce4147b6c8f8a132f772be0929d58305eb22c5d9`.

`prepare-github` fetched only public Issue/repository metadata, checked out that exact commit, and
emitted a FixTask plus preparation report and SHA-256 Manifest. Discovery selected
`tests/test_filesize.py`, Ruff, the `src`/`tests` scopes, and a missing Hatch VCS-generated version
module as a runtime-only adapter. The adapter was recorded, protected, hash-checked, and excluded
from the delivered Patch.

### Failure that changed the design

The first live v0.8 run used the new `find_symbols` tool, submitted two structured edits, and
produced a valid Git Patch. Verification could not collect tests because the frozen source checkout
did not contain the build-generated `humanize._version` module. The replacement attempt then
exhausted its tool-call budget. The run failed after 433.050 seconds and remains preserved as an
`agent_failed` artifact rather than being relabelled as success.

This showed that repository adaptation must be deterministic and must happen before model tokens
are spent. PRGuard therefore added:

- a pytest collection-readiness stage before the first provider call;
- a declarative runtime-file contract for known generated files;
- automatic protection and post-command hash checking for those files;
- exclusion of runtime-only files from changed-file policy and final delivery.

An offline replay of the exact first proposal then passed, isolating the original failure to the
environment contract rather than silently crediting a new model answer.

## Code-intelligence boundary

The Python index is lazy and local. It parses source with the standard-library `ast` module and
provides symbol definitions, imports and package re-exports, lexical references, approximate
incoming/outgoing calls, and related-test ranking. Every result identifies how it was resolved.

It is not a runtime-complete call graph. Dynamic dispatch, reflection, dependency injection,
monkeypatching, generated code, native extensions, and unresolved aliases can make relationships
incomplete or ambiguous. Index file count, source bytes, individual responses, symlinks, secret-like
paths, and the shared model-context budget are bounded and fail closed.

## Remaining boundaries and next priority

- Onboarding currently supports canonical public GitHub Issues; private repositories and Pull
  Request APIs are intentionally deferred.
- Automatic discovery is conservative and Python-specific. Unknown build systems, external
  services, unavailable plugins, or dependencies fail readiness instead of being guessed.
- Related-test selection is an initial fast gate, not a substitute for a repository's full CI.
- Structured editing currently supports exact replacement and file creation, not AST rewriting.
- The static index improves navigation but does not replace type-aware language-server analysis.

A first frozen [Reviewer net-benefit pair](reviewer-net-benefit.md) now records one regression that
passed a narrow configured gate but was independently found and repaired, plus one clean Humanize
Patch that was accepted without false block at high latency/token cost. The next product increment
should expand that evidence across a few additional repositories and use observed risk signals for
selective Reviewer routing. The decision criterion remains net defect reduction after false blocks,
latency, token cost, and unnecessary repair—not the number of Agent roles.
