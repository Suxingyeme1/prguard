# v0.13.3 phase report: reviewed external policy and runtime-aware gates

Status: implemented 2026-09-06.

## Objective

Exercise the post-FileLock compatibility work on a fresh, uncontaminated real Issue while closing
two practical gaps exposed by that case: non-standard test layouts and unverifiable host-runtime
identity.

## Product changes

- bounded discovery recognizes one unique nested Python `test`/`tests` root, ignores environment,
  build, documentation, and example trees, and fails closed when multiple roots are plausible;
- Issue test targeting uses explicit/backticked headline intent and no longer treats ordinary calls
  in a traceback as the requested symbol;
- `--policy-file` lets `start`, `fix`, `prepare-local`, `prepare-github`, and `inspect-policy` use a
  human-reviewed local TOML policy without modifying an upstream repository;
- the validated operator policy is canonicalized into preparation artifacts, while any attempt to
  override a repository-owned `.prguard.toml` is rejected;
- `prguard gate` runs a frozen FixTask and optional candidate Patch without a model or Reviewer;
- every verification command now archives the actual host/container Python runtime identity, and
  host tests inherit the active interpreter's console-script directory.

## Fresh holdout

[Locust #3207](https://github.com/locustio/locust/issues/3207) was frozen at
`5df19da06a0f8418d44094f3014ddee3b307bb55`. Automatic discovery found `locust/test`, but a full
Base run exposed missing generated UI assets, console-entry environment assumptions, and a
timing-sensitive test, so it was rejected rather than misreported as a Patch failure.

A reviewed public gate selects existing catch-response tests. The identical Task passed 12 tests
with 17 deselected under both CPython 3.12.13 and 3.13.12. A network-free evaluator was sealed
before any live Agent call and committed by SHA-256; it passes on the unchanged Base under 3.12 and
fails under 3.13. Its body and expected repair remain outside Agent context. Live Implementer and
Independent Reviewer results are pending, so this release claims holdout readiness—not resolution.

## Boundary and next priority

Runtime identity makes separate lanes auditable but does not provision a general environment
matrix. Operator policy removes hand-edited JSON but remains a human/CI assertion about which tests
matter. Candidate gates now independently enforce the frozen writable scope in addition to
protected paths. The next step is one live Implementer run on the frozen Locust task, public-gate
archival, independent review using compatibility signals, and only then the sealed 3.12/3.13
evaluator.
