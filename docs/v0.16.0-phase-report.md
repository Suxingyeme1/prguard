# v0.16.0: Studio product workspace

## Delivered behavior

- Replaced the dense “Agent cockpit” presentation with a calm local developer workspace. The
  primary path now reads as: prepare task → inspect frozen run contract → explicitly approve →
  observe real verification → inspect/download the resulting Patch and evidence.
- Split static recorded examples from authenticated local execution. attrs #1575 and Click
  #3199 are clearly labelled frozen run records; opening them never calls a model, writes source,
  or pretends a finished run is live.
- Replaced full-document MutationObserver translation with explicit Chinese/English message
  catalogs. UI language changes no longer mutate commands, hashes, source paths, user input, or
  recorded evidence.
- Separated the local API adapter from rendering. The adapter retains authenticated session/run
  recovery and bounded polling; the view presents a connection problem as observation loss rather
  than as task cancellation.
- Kept the existing authority boundary intact: terminal startup selects repository, provider,
  policy, and host/container mode; the browser supplies only Issue and requested Git version.
  The local result says “passed verification,” not “review-ready,” because this entry still runs
  Fix without Independent Reviewer.

## Verification scope

The release adds Studio asset-contract coverage in addition to the existing real HTTP, artifact
integrity, Host/Origin, token, request-schema, and approval tests. JavaScript syntax is checked for
the authored static assets, and the package wheel is inspected to ensure the browser entry ships
the current assets. Full regression: **302 passed**; Ruff passed.

## Current limits

This is a product-quality local **Fix** workspace, not a remote code-execution service and not yet
a browser UI for independent review. It has no browser cancellation, multi-user hosting, persistent
job scheduler, or restart recovery. A transient browser disconnect does not stop the bounded local
task. The next functional product increment is to surface the existing composed fix --review
pipeline as a deliberate, separately reviewed local API rather than simulating Reviewer state in
the frontend.
