# v0.13.6 phase report: fresh attrs holdout and server offboarding

## Outcome

PRGuard resolved a new, previously unused real-repository Issue under a precommitted evaluator.
The run also closed the remaining company-server validation work: Linux x86_64 and CPython 3.14
host execution are archived, the low-privilege/evaluator boundary was exercised, and the available
snap-packaged Docker worker was explicitly rejected rather than weakened.

- Base Commit: `6851ab593cd25f3c14393e9355d57d22bec2a074`;
- runtime: CPython 3.14.2 on Linux x86_64;
- public gate: `pytest -q tests/test_annotations.py`, 47 Base tests;

  `2aaaea188d5b9eafd25cdacf0e54b31f91a43aaf44ac315d3e40cfa8f7222e56`;

The evaluator was committed by hash and failed on the unchanged Base before the provider was
called. Preparation and Base-gate Manifests both verified.

## Implementer and Reviewer

The live DeepSeek `deepseek-v4-pro` Implementer used 24 bounded repository tools and submitted one
Patch after 136.8 seconds. It unwrapped the Python 3.14 forward-reference argument before attrs'
existing `ClassVar` prefix check and added two tests. PRGuard replayed the changed tests against
Base, where two failed, and accepted the candidate only after all 49 public tests passed. The Fix
Manifest and candidate Patch hash verified.

The Independent Reviewer used a fresh context and a 12-call read budget. It returned `accept` with
zero findings after 190.5 seconds. The Review Manifest verified. No repair was triggered.

Only then was the evaluator revealed. It passed on the candidate. A wider differential run recorded
1,385 passes and two packaging-environment failures on Base, then 1,388 passes and the same two
failures on the candidate. Those failures come from the development version string created by the
frozen checkout and are not candidate regressions. The core repair direction matches the later
inspected upstream change.

## Container worker qualification

The digest-pinned reference image was present, but the host uses snap-packaged Docker 29.6.1. One
probe showed Snap could not access a cidfile below `/srv`; relocating the probe allowed startup to
advance, after which the runtime rejected `/usr/local/bin/python3` when
`no-new-privileges` was enabled. PRGuard classified both as infrastructure failures and never
retried with weaker controls.

Therefore this server is qualified for explicitly trusted host-mode tests, not for PRGuard's
container mode. The probe archive is retained with SHA-256
`f7a7f69e577e7f0a1bfabb19ab9dbcd32398acf1e97d2e9600904a1bbf22cd7d`.

repository navigation, and provider support. Running untrusted repositories in container mode
requires a separately qualified worker with a compatible rootless Docker or Podman setup.
