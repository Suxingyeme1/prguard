# v0.10.5 phase report: a green-gate defect caught by Independent Review

Status: implemented 2026-09-03.

## Objective

Test the frozen v3 router on a genuinely defective real-world Pull Request, measure whether the
Independent Reviewer adds information beyond the deterministic gate, retain environment failures,
and version any deterministic correction without rewriting prior evidence.

## Real-repository observations

Two server runs used the non-root `prguard` account and independent DeepSeek Reviewer contexts:

| Case | Evaluator label | Deterministic gate | v3 route | Reviewer | Review cost |
| --- | --- | --- | --- | --- | --- |
| python-dotenv #600 | clean | 217 passed, 1 skipped | `skip` 0/5 | accept, 0 findings | 384.1 s; 299,307 input + 19,934 output tokens |
| Click #3199 | defective | 1323 passed, 21 skipped, 1 xfailed; 9 changed tests passed | `review` 23/5 | request changes, one P2 | 291.6 s; 246,900 input + 13,992 output tokens |

The Click candidate was not a synthetic mutation. It was a real proposed fix for Click #3145 and
passed the repository's full declared suite. The Reviewer independently identified that moving
internal parameter lookup to `Context._lookup_default()` bypassed subclasses overriding the public
`Context.lookup_default()` method. An evaluator-only custom Context check honored the override at
Base and returned the internal unset sentinel with the candidate. This reproduces the defect that
caused the upstream candidate to be rejected; the evaluator and maintainer feedback were never in
the Reviewer context.

This is direct incremental benefit: the Harness did not already know or block the defect, while the
Reviewer supplied the file, symbol, evidence, and a reproducible condition.

## Routing v4

The Click verification first ran unfiltered `pytest -q`, then a Harness-derived targeted replay of
the changed test module. v3 retained only the later targeted scope. `review-routing-v4` aggregates
successful pytest commands so a full-suite run cannot be downgraded by a subsequent targeted replay.

The exact Click route remains `review`, changing only from 23/5 to 18/5 by removing the spurious
`no_explicit_unchanged_test_evidence` factor. Its remaining factors are changed candidate tests,
incomplete static analysis, and medium Patch size. The python-dotenv route remains `skip` 0/5.

## Environment evidence

The first Click Review attempt failed readiness before any model call because the release
environment had pytest 9.1.1 while the frozen repository lock expected 9.0.1; a deprecation warning
became an error. The failed report consumed zero model tokens and remains hash-bound. After aligning
the dependency to the frozen lock, the same Task completed. This is recorded as an environment
failure, not a model failure.
