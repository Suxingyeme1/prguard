# v0.17.0: Studio review and task inspection

## Delivered

- Added an optional independent-review workflow to the local browser entry. The operator enables
  it at startup; the user selects it before preview and approval. The adapter executes the existing
  Issue-to-PR pipeline with fresh Reviewer and repair provider instances.
- Bound workflow, Reviewer settings, stage budgets and scripted input contents into the frozen
  approval envelope. The browser cannot change providers or workflow at start time.
- Displayed source-linked findings, review verification, routing details and any controlled repair.
  Review failure withholds the final Patch even after a green initial Fix. An accepted repair is
  labelled as passing verification, without claiming another Reviewer pass.
- Added session task history, selection and connection recovery. Late requests cannot replace a
  newly selected task, unchanged responses do not redraw the page, and an uncertain start response
  is recovered through a state read instead of an automatic second start.
- Added file-grouped unified diffs with old/new line numbers and addition/deletion highlights.
  Copying and verified downloads retain the original Patch. Chinese/English controls, keyboard
  tabs, detail expansion and scroll/focus preservation support inspection.
- Added finer progress events to the composed pipeline and review runners. The callback contract
  exposes allowlisted metadata and isolates observer errors from execution decisions.

## Automated verification

- Python full regression: **314 passed**, including HTTP authentication and origin checks, immutable
  approval, real Git/pytest execution, Reviewer-failure delivery blocking, a local scripted
  review/repair cycle, session history, artifact integrity and progress-observer isolation.
- Node built-in test runner: **11 passed** for request lifecycle/race recovery and unified diff
  parsing. This is state/parser automation, not an automated full-browser end-to-end suite.
- Ruff passed; browser JavaScript syntax and wheel packaging are checked for release.

The local review/repair test changes all external scripted input files after preview and confirms
the already-frozen payloads are executed. Its Reviewer identifies a lowercasing regression, and
the delivered repair restores that behavior. The fixture test command checks the Issue's `None`
case; it is not claimed as an independent, comprehensive regression oracle.

## Manual checks and boundaries

The local browser walkthrough runs the clamp demo with actual Git worktrees, two Fix attempts,
pytest, independent candidate verification and five hash-checked delivery files. Model responses
are scripted and labelled as such. No paid model call or new real-repository benchmark was run
for this release; prior upstream evidence remains unchanged.

Manual UI checks covered the 1280-pixel desktop layout, 390-pixel narrow layout, Chinese/English
switching, result tabs, the Patch download action, browser refresh and returning from a new draft
to an existing completed task. Refresh preserved the same result and did not add a task. Download
byte/hash integrity is additionally checked through the real HTTP integration tests.

This remains a single-user loopback service. Task history covers only the current process (at
most 50 tasks), while disk artifacts persist. There is no browser cancellation, server-restart
recovery, remote job scheduler or standalone candidate-upload Review form. Closing the browser
does not stop the worker; normal service shutdown waits for bounded verification to finish.
UI progress records are diagnostic files outside the recursive run Manifest.
