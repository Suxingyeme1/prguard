# PRGuard v0.13.5 phase report

Date: 2026-09-07

## Outcome

The first Linux-host execution of the frozen Locust #3207 holdout completed. It is an honest
negative result: PRGuard produced and accepted a one-line Patch that passed the declared public
gate but did not resolve the version-specific defect. Independent Review repeated the false accept
with both 12 and 24 source-read calls.

This run therefore establishes a concrete capability boundary rather than a task-resolution claim.
It also produced a narrow hardening change: required mapping access changed into a fallback is now
surfaced to the Reviewer, and both Agents are instructed to trace missing state to its producer and
object-lifetime boundary.

## Frozen execution

- repository: `locustio/locust`
- Base Commit: `5df19da06a0f8418d44094f3014ddee3b307bb55`
- public gate: `pytest -q locust/test/test_http.py -k catch_response`
- live provider/model: DeepSeek `deepseek-v4-pro`, high reasoning
- execution identity: unprivileged `prguard` account on Linux; evaluator storage remained root-only
- Agent-visible solution material: none; the evaluator body, Gold Patch, and later upstream repair
  were withheld until the live Implementer and Reviewer artifacts were frozen

The public Base gate passed 12 tests with 17 deselected under CPython 3.12.4 and 3.13.5 on the
server. The precommitted evaluator passed on the unchanged 3.12 Base and failed on the unchanged
3.13 Base, confirming that the target was version-specific rather than an invalid universal test.

## Implementer result

The Implementer made 24 bounded read/tool calls and changed one line in `locust/clients.py`:

```diff
-            self.url = self.request_meta["name"]
+            self.url = self.request_meta.get("name", self.url)
```

The public gate passed. The sealed 3.13 evaluator still failed because the Patch suppressed the
`KeyError` at the consumer but did not repair the earlier ownership/lifetime corruption. The
Implementer run consumed 243,533 input tokens, 7,716 output tokens, 220,928 cached tokens, and
159.14 seconds.

## Independent Review result

| Reviewer budget | Verdict | Findings | Duration | Input / output tokens |
| ---: | --- | ---: | ---: | ---: |
| 12 calls | accept | 0 | 67.75 s | 118,548 / 2,335 |

Both Reviewers inspected the changed protocol method and surrounding metadata construction. Both
treated the fallback as safe because the key was expected to exist in normal construction. Neither
followed that contradiction backward to the invalid object lifetime described by the Issue. The
second run shows that more context budget alone does not correct a missing review criterion.

## Sealed evaluator and upstream check

After the Agent artifacts were frozen, the evaluator was attached to Base, candidate, and the
upstream repair:

- CPython 3.13 Base: failed as precommitted;
- CPython 3.13 candidate: failed;
- upstream repair: passed the evaluator and 28 relevant public tests;
- CPython 3.12 Base: evaluator passed, so PRGuard correctly rejected that lane as a changed test
  that did not demonstrate FAIL_TO_PASS on Base.

The evaluator source remains unpublished. Public evidence carries only its pre-run SHA-256
commitment, outcomes, and the recursive hashes of root-only raw artifacts. The upstream repair was
used only after reveal and is not presented as Agent output.

## Product changes

1. Implementer instructions now require locating the violated invariant and producer/ownership
   boundary before editing a downstream failure site.
2. Reviewer instructions apply the same standard to `.get()` defaults, attribute fallbacks,
   swallowed exceptions, and early returns.
3. The bounded AST comparison counts string-key subscripts and `.get()` calls inside changed public
   callables. Reducing a required access while adding the matching fallback creates an auditable
   compatibility signal.
4. The signal cannot block a Patch by itself. This preserves the fact boundary between static
   suspicion, model judgment, and deterministic verification.

## Boundary and next step

This release does not claim Locust #3207 resolution or improved held-out Reviewer accuracy. The
case is now contaminated and serves only as a regression fixture for the new deterministic signal.
The next valid quality step is a fresh, unseen real-repository holdout with its evaluator committed
before either Agent runs. Product work should continue to prioritize Issue-to-Patch usability and
source understanding over adding another Agent role.
