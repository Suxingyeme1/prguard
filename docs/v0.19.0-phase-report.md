# v0.19.0: Runnable review repair and correct regression references

## Delivered

- Added a second selectable offline Studio case. The initial normalizer Patch passes the existing
  test but loses lowercase behavior. A scripted Reviewer identifies the regression, then a
  controlled repair restores the code and adds a regression test.
- The review result exposes the new test's actual reproduction command, failing output and
  reference Patch SHA-256. Summary separates initial implementation from review repair; the
  attempt metric is explicitly labelled as implementation-stage attempts.
- Fixed a real Harness false block discovered while building the demo. A candidate-introduced
  regression should reproduce on that candidate, not an originally correct Base. Review repair
  now freezes the reviewed candidate before review and uses its hash-bound snapshot for the test
  probe. Initial Fix keeps its existing Base reference gate.
- Archived the reference Patch in the Manifest and made replay use it, independent of later
  changes to the external input. Added mode/pair validation, bounded regular-file/hash checks,
  protected-path checks, and explicit reference metadata in JSON/Markdown reports.
- Recorded the decision in ADR 0035. Version markers are schema 1.4.0, Harness 0.4.0 and
  review-repair-v8. Legacy probe field names remain documented for compatibility.

## Verification

- **335 Python tests passed**, full suite, 157.88 seconds.
- **12 Node tests passed** for state, Patch parsing and localization.
- **6 real-browser tests passed**, Playwright with the installed Google Chrome, 27.6 seconds.
  The new case covers workflow locking, repair summary, source-linked finding, the failing
  reproduction record and the delivered code-plus-test Patch.
- Ruff, JavaScript syntax checks and `git diff --check` passed.
- Built the source distribution and wheel. An isolated wheel installation imported version
  0.19.0, its CLI and all seven packaged Studio assets successfully.
- Manually ran the new case through the browser approval flow and inspected the review page:
  `normalize(' HELLO ')` produced `HELLO` instead of `hello` on the reference; final verification
  passed after repair. The recursive workflow Manifest passed the integration check.

New security/integration checks cover an appropriate test that passes Base but fails the candidate,
vacuous tests, reference hash mismatch, symlink inputs, malformed/protected-path reference Patches,
reference schema restrictions, source preservation and replay after external-reference mutation.

## Facts and remaining limits

Model replies in both offline cases are predefined. Git, worktree creation, pytest, HTTP approval
and artifact verification are real. No paid model call, company server operation or new upstream
evaluation was performed. This report does not claim a completed remote CI run.

A failing test group is reproduction evidence, not proof that every test is meaningful or the
Issue is fully covered. Passing repair verification is not a second independent review. Host
execution remains for trusted repositories. History is still process-local; standalone review
upload, cancellation and durable history remain future product work. Runtime dependencies remain
unchanged.

## Try it

```bash
uv run --no-editable --extra demo prguard studio --enable-independent-review
```

Choose `测试通过 → 审查发现回归 → 修复并补测试`, preview and approve the frozen plan,
then open `审查` → `新增测试的复现记录`. Compare the failing reproduction with final
verification and inspect the two changed files in `补丁`.
