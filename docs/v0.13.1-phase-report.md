# v0.13.1 phase report: live holdout and evidence-boundary hardening

Status: implemented 2026-09-05.

## Objective

Run the frozen FileLock #606 Issue through a live Implementer and independent Reviewer without
exposing evaluator material, then turn every observed failure into a general product boundary
rather than presenting a green public test suite as proof of Task Resolution.

## Live holdout result

The first DeepSeek candidate exhausted the original read-turn loop. After terminal-turn hardening,
it produced a five-file Patch and 24 new tests, but those tests imported a candidate-only private
symbol and exited 2 during the Base probe. PRGuard now rejects that outcome instead of counting it
as FAIL_TO_PASS.

A controlled resume replayed the exact frozen candidate as attempt 0 and used a live DeepSeek call
for the one permitted repair. Attempt 1 changed the tests so they collected on Base and produced
eight assertion failures. The candidate passed the full public gate with **563 passed, 33 skipped**
and all **24 changed tests passed**. The Fix Manifest verified.

The independent Reviewer required additional provider hardening. A 24-read review returned after
the 900-second task deadline; a 12-read run showed that DeepSeek thinking mode could request a tool
removed from the terminal tool list, and the API rejected forced tool choice while thinking. The
final protocol disables thinking only for the terminal call, forces `submit_review`, records
protocol violations, and permits one no-read recovery turn. The successful review completed in
172.893 seconds, accepted the Patch, and emitted two P3 findings. Its Manifest verified.

Only then was the evaluator opened. It rejected the candidate: the Patch globally changed the
existing default exception behavior, while the upstream-compatible contract preserves that default
and exposes grouping as an opt-in public policy. The independent Reviewer missed this breaking
default. The case is recorded as a **false accept and unresolved task**, not a model success.

## Product changes

- terminal-only submission after the final Implementer or Reviewer read;
- DeepSeek Reviewer terminal compatibility for thinking and forced tool choice;
- one bounded recovery from an invalid terminal tool call;
- one repair for structured-edit conflicts and invalid Agent-authored Base tests;
- pytest Base probes require exit code 1, rejecting collection/import failures;
- Reviewer instructions explicitly compare public signatures and default behavior with Base;
- provider failures continue to retain token, response, tool-call, and protocol metadata.

## Boundary

The accepted Harness result means only that the candidate passed the declared public gate at the
frozen Commit. The held-out evaluator is the Task Resolution authority for this case. Because the
evaluator is now known, FileLock #606 cannot be reused as a clean holdout for prompt tuning or a
second model attempt.
