# v0.10.3 phase report: versioned Reviewer-routing correction

Status: implemented 2026-09-02.

## Objective

Correct the known PrettyTable False Skip without rewriting `review-routing-v1`, adding a
repository-specific exception, or claiming deployment readiness from a post-hoc replay.

## Policy change

`review-routing-v2` adds one deterministic factor with weight 5, equal to the Review threshold:

```text
stateful_nested_factory_changed
```

The factor requires a changed Python function to directly return one of its nested classes and at
least one `self.*` attribute to be written by two or more methods of that class. Evidence records
the changed symbol, returned class, and a bounded attribute list. It uses candidate AST only; it
does not inspect Issue wording, evaluator labels, model reasoning, repository identity, or execute
repository code.

The direct-return boundary avoids treating a return inside an enclosed method as a factory return.
A boundary test also proves that an ordinary nested value class whose state is written only during
initialization does not receive the factor.

## Activation boundary

The replay summary records `activation_decision: not_ready`. PrettyTable was the failure used to
design the signal, and no independent holdout repositories have been evaluated under v2. This is
corrective evidence, not an unbiased False-Skip or False-Route estimate.

`always` remains the compatible default mode. `shadow` measures the selective recommendation while
still running Review, and only an explicit `selective` task may skip it. The next decision gate is
a small manually labelled holdout set with both ordinary stateful implementations and genuinely
low-risk changes.
