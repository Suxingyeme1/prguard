# v0.15.0: Studio local execution

## Delivered behavior

- `prguard studio` opens the bilingual browser against an authenticated loopback adapter.
- The offline demo executes real Git/worktree/pytest verification with scripted model proposals:
  a failed first attempt, failure feedback, one passing repair, and real Patch/Manifest delivery.
- A CLI-configured repository/provider can run an Issue from the browser using existing local
  onboarding. The frozen Task, resolved commit, test commands, edit paths, and execution mode are
  displayed before confirmation.
- Ordered events are polled during execution. Both attempts show actual command outcomes/output;
  the final Patch and report/Manifest downloads are hash-checked. Refresh reconnects to the current
  run without resubmitting it.
- Static evidence replay and the hosted URL remain usable. The new Local workspace tab explains
  how to launch the local adapter; no browser credential or cloud-to-local connection is required.
- Wheel builds include the authored frontend, so the browser entry is available after installation.

## Verification scope

Full regression: **301 passed**. Ruff checks passed. The wheel includes the adapter and frontend
assets, and the installed CLI exposes `studio --help`. Local instructions use `--no-editable` to
avoid this workstation's stale editable-install metadata.

The hosted update was attempted, but the Sites connector returned `project_not_found` for the
existing configured Site. The original project identifier is preserved; no replacement Site was
created. This release's updated browser workspace is available locally and in repository source;
the previous hosted publication must not be represented as updated.

Real HTTP integration tests exercise the offline failure-repair loop and a configured local
repository fix. The latter moves the original HEAD after preparation and proves the approved
commit remains frozen and original source unmodified. Security tests exercise token checks,
cross-origin and Host rejection, forbidden request fields, explicit approval, duplicate start,
modified Task files, artifact integrity and symlinks, and the static-file allowlist.

## Current limits

This browser entry executes Fix, not the composed Independent Reviewer pipeline. Result views say
Review was not run. Real provider operation reuses the existing backend; this increment's new
end-to-end executions use scripted proposals and do not claim new live-model evaluation results.
One worker runs per local session. Server restarts do not restore in-memory jobs; completed disk
artifacts persist. Closing waits for current verification rather than interrupting subprocesses.
Host mode still executes trusted repository code with the current account. The adapter adds no OS
sandbox. The next product step is browser integration of `fix --review` and a deliberate task
cancellation design.
