# v0.14.0 phase report: PRGuard Studio evidence cockpit

## Outcome

PRGuard now has a browser-based product demonstration rather than relying only on terminal output
and JSON artifacts. The Studio presents the complete Issue-to-Patch and Review-to-Repair journeys
as inspectable evidence chains.

## Implemented

- responsive three-panel workspace for Task boundary, live Trace replay, and delivery evidence;
- switchable `attrs #1575` Fix and `Click #3199` Review/Repair cases;
- animated stage and Trace Event playback with public gate, Patch, review, and evaluator outcomes;
- Patch, structured review, artifact, and recursive Manifest views;
- downloadable delivery summary plus direct links to upstream Issues and checked public evidence;
- explicit read-only semantics: no model call, source write, or fake live-run claim;
- dependency-free static build with a one-command local server and hosting configuration.

## Evidence boundary

The interface mirrors facts already preserved under `evidence/attrs-1575-holdout` and
`evidence/click-controlled-repair`. It does not publish hidden evaluator bodies or Gold Patches.
ADR 0026 records why browser control of live execution is deferred to an authenticated local
adapter.

## Verification

- JavaScript syntax checked with `node --check`;
- every local HTML asset fetched successfully through an HTTP server;
- the existing Python unit, integration, contract, and security suite remains the regression gate.

## Next boundary

Add a local adapter that translates the existing structured Progress/Trace stream into server-sent
events. It should start only after the current deterministic onboarding has frozen the repository,
Commit, Issue, commands, writable paths, and explicit execution mode.
