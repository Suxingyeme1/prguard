# v0.13.0 phase report: guided real-repository entry and stronger edit/test evidence

Status: implemented 2026-09-04.

## Objective

Move the product one step closer to an everyday Coding Agent: make a real local run approachable
without Task JSON, let structured edits address repeated code safely, and prevent an Agent-authored
test from being accepted merely because it passes after the Patch.

## Implementation

`prguard start` is a dependency-free guided terminal session. It accepts or prompts for an ordinary
Issue, previews the requested and resolved Git Commit, discovered pytest/Ruff argv, writable and
protected paths, and execution boundary, then invokes the same preparation and FixRunner used by
the non-interactive CLI. It never chooses host trust automatically.

The edit protocol now supports SHA-256-guarded inclusive line ranges and unambiguous Python
definitions alongside unique text replacement and file creation. `read_file` returns the hash of
the selected raw range, PRGuard rechecks it immediately before mutation, and Git authors the final
unified diff.

Candidate Fix/Review tasks set a Harness policy that executable changed Python tests must fail in a
fresh Base worktree containing the candidate tests but not candidate source. Tests that pass on
Base are policy-blocked; timeout and infrastructure outcomes remain distinct. AST-equivalent
comment/format-only changes skip the FAIL_TO_PASS rule and continue through the ordinary gate.

## Boundary

The terminal entry is intentionally line-oriented rather than a full-screen OpenCode-style client.
The Base probe establishes that an executable test distinguishes Base from Candidate; it cannot
establish that the test states the right requirement. FileLock is currently holdout preparation and
Base-readiness evidence, not a fourth live-model resolution claim.
